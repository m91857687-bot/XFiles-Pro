# XFiles Pro — ARCHITECTURAL DECISIONS (سجل القرارات الهندسية)

يوثق هذا السجل القرارات المعمارية الرئيسية (Architecture Decision Records - ADRs)، مع توضيح السياق، والخيارات المطروحة، والسبب وراء اتخاذ كل قرار، والآثار المترتبة عليه.

---

### ADR-001: اعتماد مجلد التوثيق الدائم (`project_docs/`) كمصدر أحادي للحقيقة
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** في المشاريع المعقدة وطويلة الأمد، قد تتبدل جلسات التطوير أو يتغير نموذج الذكاء الاصطناعي أو حساب المطور، مما يؤدي إلى فقدان السياق أو إعادة كتابة الأكواد من الصفر وتخريب البنية.
- **القرار:** إنشاء مجلد دائم ومستقل باسم `project_docs/` يحتوي على 10 ملفات تغطي جميع جوانب المشروع المعمارية والتنفيذية، ويتم تحديثها باستمرار لتكون المرجع الإلزامي لأي جلسة جديدة.
- **الآثار:** يضمن نقل المشروع واستمراريته بنسبة 100% بين أي نماذج ذكاء اصطناعي أو مطورين بشريين دون أي ارتباك أو تكرار.

### ADR-002: معمارية نظام اللغات والدعم الكامل لـ RTL و LTR
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** التطبيق موجه لجمهور دولي ويدعم 4 لغات (العربية، الإنجليزية، الإسبانية، الفارسية) مع اشتراط شاشة اختيار عند أول تشغيل وتطبيق فوري بدون إعادة تشغيل النشاط أو تدمير الحالة.
- **القرار:** استخدام Jetpack DataStore لحفظ رمز اللغة، وإدارة لغة التطبيق وتحديث السياق (Localized Context) على مستوى Jetpack Compose، مع الاعتماد الحصري على مجلدات الموارد الرسمية (`values`, `values-ar`, `values-es`, `values-fa`) دون أي نصوص برمجية صريحة (Hardcoded strings).
- **الآثار:** تجربة تبديل فورية سلسة، ودعم كامل للاتجاه من اليمين لليسار (RTL) للعربية والفارسية ولليسار لليمين (LTR) للإنجليزية والإسبانية.

### ADR-003: نظام السمات البصرية الأربع (Classic, Midnight, Royal, System)
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** توفير تجربة بصرية متميزة تنافس التطبيقات الاحترافية وتلبي تفضيلات المستخدمين المختلفة (أبيض وأسود عالي الوضوح، داكن موفر للطاقة، فاخر، ومتوافق مع نظام أندرويد).
- **القرار:**
  - Classic: أبيض وأسود نقي عالي التباين (الافتراضي).
  - Midnight: أسود فاحم (OLED Black #000000) مع رمادي داكن.
  - Royal: أسود داكن مع عناصر ذهبية ملكية (#D4AF37 / #FFD700).
  - System: تكامل مع Material You و Dynamic Colors على أندرويد 12+.
- **الآثار:** حفظ التفضيل في DataStore وتطبيقه فورياً عبر `MaterialTheme` المركزي دون استخدام أي ألوان عشوائية داخل الواجهات.

### ADR-004: استراتيجية الفهرسة الدائمة للملفات (Room + SQLite FTS5)
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** استكشاف ملايين الملفات وإعادة قراءتها بالكامل عند كل تشغيل يستهلك المعالج والبطارية ويتسبب في بطء فادح.
- **القرار:** بناء قاعدة بيانات محلية عبر Room مدعومة بجدول افتراضي FTS5 للبحث النصي الفوري، وتحديث السجلات تزايدياً في الخلفية باستخدام `ContentObserver` للملفات الجديدة/المعدلة/المحذوفة، بالإضافة لتحديث الفهرس تلقائياً بعد كل عملية تتم داخل التطبيق.
- **الآثار:** فتح فوري للتطبيق ونتائج بحث في أجزاء من الثانية مع الحفاظ على استهلاك الذاكرة والبطارية.

### ADR-005: معمارية النظافة وفصل الاهتمامات (Clean Architecture + MVVM)
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** الحفاظ على كود التطبيق منظم وقابل للتطوير والاختبار وتجنب الملفات العملاقة التي تضم الواجهات والبيانات في مكان واحد.
- **القرار:** تقسيم المشروع إلى 3 طبقات واضحة (Domain, Data, UI) مع حالات استخدام فردية (Use Cases) لا تتجاوز حدود مسؤوليتها، وتنفيذ جميع العمليات الثقيلة داخل خيوط `Dispatchers.IO` بواسطة Coroutines.
- **الآثار:** سهولة إضافة ميزات جديدة، أداء عالي وسلاسة 60/120 إطار في الثانية للواجهة، وتغطية اختبارية موثوقة.

### ADR-006: أمان الخزنة والتشفير المعتمد على عتاد الجهاز (Android Keystore + AES-256-GCM)
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** تتطلب الخزنة حماية قصوى لبيانات المستخدم السرية دون الاعتماد على مفاتيح ثابتة في الكود أو خوادم خارجية.
- **القرار:** توليد وحفظ مفاتيح التشفير داخل شريحة الأمان العتادية (Android Keystore / Secure Enclave)، وتشفير محتوى الملفات بخوارزمية AES-GCM بقوة 256 بت مع التدفق المباشر للبيانات عبر `CipherOutputStream` لتفادي نفاد الذاكرة.
- **الآثار:** حماية مصرفية قوية ضد استخراج الملفات المشفرة حتى في حال الوصول للجهاز.

### ADR-008: توحيد الـ namespace ونقل حزم كوتلن واعتماد AppContainer
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** توحيد `namespace` و `applicationId` على `com.xfiles.pro` ونقل الحزم إلى الهيكل الصحيح مع إنشاء طبقات core و domain و data وتأسيس حاوية حقن التبعيات.

### ADR-009: تطبيق اللغة والاتجاه فورياً في Compose عبر Dynamic Context Wrapping
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** فرضت متطلبات المرحلة الثانية تغيير لغة التطبيق واتجاه الواجهة (RTL/LTR) فورياً دون الحاجة إلى إعادة تشغيل الـ Activity، ودون فقدان حالة الشاشات أو بيانات المستخدم.
- **القرار:** 
  1. إنشاء مكون `LocalizedApp` على قمة شجرة Compose.
  2. إنشاء سياق مهيأ ديناميكياً باستخدام `context.createConfigurationContext(newConfig)` وتعيين `Locale` المختار.
  3. توفير السياق المعدل والتهيئة المعدلة واتجاه الواجهة عبر:
     ```kotlin
     CompositionLocalProvider(
         LocalContext provides localizedContext,
         LocalConfiguration provides localizedConfig,
         LocalLayoutDirection provides layoutDirection
     )
     ```
  4. حفظ واسترجاع التفضيلات وحالة أول تشغيل عبر `LanguagePreferences` باستخدام Jetpack DataStore على `Dispatchers.IO`.
- **الآثار:** استجابة فورية بدون وميض للشاشة وبدون إعادة إنشاء الـ Activity وبدون فقدان أي حالة للمستخدم، مع دعم كامل للـ RTL للعربية والفارسية والـ LTR للإنجليزية والإسبانية عبر كافة إصدارات Android من API 24 إلى API 36.

### ADR-010: معمارية نظام السمات البصرية الأربع وتوحيد Color Tokens و DataStore
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** تتطلب المرحلة الثالثة بناء نظام سمات يدعم 4 خيارات (Classic, Midnight, Royal, System)، مع حفظ الاختيار في DataStore واستعادته، والتبديل الفوري بدون إعادة تشغيل الـ Activity، مع منع إنشاء نسختين من DataStore لنفس الملف، وتوحيد الألوان عبر نظام Tokens مركزي بدلاً من الألوان المتناثرة.
- **القرار:**
  1. إنشاء نموذج `ThemeMode` وحاوية الألوان `XFilesColorTokens` و `ColorTokens.kt` لتضمين الرموز الـ 13 الرئيسية.
  2. إعادة استخدام نفس امتداد `Context.dataStore` في `ThemePreferences` وربط المستودع `ThemeRepositoryImpl` عبر `AppContainer`.
  3. حقن الرموز عبر `CompositionLocalProvider(LocalXFilesTokens provides tokens)` وتغليف التطبيق بـ `XFilesTheme(themeMode = ...)`.
  4. استجابة ديناميكية لسمة النظام (System Mode) مع ألوان Dynamic Colors على Android 12+ والتبديل التلقائي لنمط Dark/Light.
  5. إنشاء `ThemePickerDialog` لمعاينة الألوان وتطبيق السمة فوراً.
- **الآثار:** تبديل فوري خالي من الوميض، ألوان متناسقة وعالية التباين، توافق تام مع اللغات الأربع (16 تركيبة تم اختبارها بنجاح)، وحماية تامة ضد أخطاء ازدواجية DataStore.

### ADR-011: معمارية الواجهة الرئيسية والتنقل التكيفي (Main UI Shell & Adaptive Navigation)
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** تتطلب المرحلة الرابعة بناء هيكل واجهة رئيسية احترافي وشامل لتطبيق XFiles Pro يدمج 5 وجهات رئيسية (`HOME`، `FILES`، `MEDIA`، `TOOLS`، `SETTINGS`)، مع شريط علوي موحد، لوحة وصول سريع ديناميكية بـ 8 أقسام، منطقة استعراض ملفات تدعم التبديل بين القائمة والشبكة (List/Grid)، شريط مسار تفاعلي، وتصميم متجاوب يتكيف تلقائياً بين الهواتف المحمولة والأجهزة اللوحية/الشاشات العريضة.
- **القرار:**
  1. اعتماد `NavDestination` كتعداد نوعي مركزي (Type-safe Enum) للوجهات الخمس مع أيقونات التحديد والأيقونات العادية وعناوين الموارد المترجمة.
  2. بناء `XFilesAppShell` باستخدام نمط Adaptive Layout الموصى به رسمياً في Material 3:
     - للشاشات العادية (`< 600dp`): استخدام `NavigationBar` سفلي مريح لليد الواحدة.
     - للشاشات العريضة والأجهزة اللوحية والوضع الأفقي (`>= 600dp`): استخدام `NavigationRail` جانبي متجاوب يمنع تمدد العناصر ويوفر راحة قصوى.
  3. توحيد الشريط العلوي في `XFilesTopAppBar` مع دعم نقاط الربط للبحث وتغيير طريقة العرض (List/Grid) والقائمة الفرعية ومراعاة اتجاه الرموز (AutoMirrored).
  4. دعم سلوك زر الرجوع الذكي `BackHandler`: عند الضغط على زر الرجوع في أي قسم فرعي، يعود التطبيق بسلاسة إلى قسم `HOME` بدلاً من إغلاق التطبيق فجأة، ولا يخرج من التطبيق إلا عند الرجوع من الواجهة الرئيسية.
  5. ربط شاشة الإعدادات `SettingsScreen` مباشرة بـ `LanguageViewModel` و `ThemeViewModel` ونوافذ الاختيار `LanguagePickerDialog` و `ThemePickerDialog` لتوفير تجربة مستخدم موحدة.
- **الآثار:** واجهة فائقة السلاسة والاستجابة، توافق كامل 100% مع اللغات الأربع (RTL/LTR) والسمات الأربع، وتأسيس معماري متين وجاهز لاستقبال محرك الملفات والفهرسة الدائمة في المرحلة الخامسة.

### ADR-012: معمارية محرك التخزين والدمج الآمن بين SAF و MediaStore واستراتيجية النسخ المحمي
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد (Accepted)
- **السياق:** تتطلب المرحلة 5A الوصول الحقيقي لوحدات التخزين وإجراء عمليات الملفات (CRUD) مع الالتزام التام بقيود Scoped Storage، وعدم الاعتماد على إذن `MANAGE_EXTERNAL_STORAGE` الشامل، ومنع أي فقدان للبيانات عند فشل النسخ، ومعالجة فروقات واجهات `StorageManager` بين إصدارات أندرويد من API 24 وحتى API 36.
- **القرار:**
  1. اعتماد المعمارية ثلاثية المسارات (Tri-Path Access):
     - استخدام `SafManager` للتعامل المباشر مع واجهات Storage Access Framework عبر `DocumentsContract` و `ContentResolver` لحفظ أذونات الـ URI الدائمة والتحقق من عدم سحبها.
     - استخدام `MediaStoreManager` للوصول السريع لوسائط الصور والفيديوهات والصوتيات والتنزيلات العامة والملفات الأخيرة.
     - استخدام مسار File APIs فقط كمسار سريع للمسارات العامة والمتاحة دون اعتبارها التفافاً على النظام.
  2. اعتماد استراتيجية النسخ المحمي (Safe Streaming & Atomic Commit):
     - كتابة البيانات المتدفقة (بمصفوفة 64KB) في ملف مؤقت `.tmp` أولاً.
     - التحقق التام من مطابقة البايتات والحجم قبل إتمام التسمية النهائية.
     - عدم حذف المصدر نهائياً في عمليات النقل إلا بعد اكتمال النسخ والتحقق من سلامته.
     - في حال فشل أي عملية، يُحذف الملف المؤقت فوراً ويبقى المصدر كما هو دون أي فقدان للبيانات.
  3. إدارة تعارض الأسماء عبر استراتيجيات صريحة: `AUTO_RENAME` (مثل `name (1).ext`)، و `OVERWRITE`، و `SKIP`.
  4. فصل منطق التصفح والعمليات داخل `FilesViewModel` وحقن التبعيات عبر `AppContainer`.
- **الآثار:** أمان مصرفي لبيانات المستخدم، صفر فقدان للبيانات، سرعة استجابة عالية بدون تجميد للواجهة، وتمرير 11 اختباراً جديداً ليصل الإجمالي إلى 86 اختباراً بنسبة نجاح 100%.

### ADR-013: محرك الفهرسة الدائمة للملفات وتدقيق FTS والفرز التزايدي و WorkManager
- **التاريخ:** 2026-11-02
- **الحالة:** معتمد نهائياً بعد التدقيق الهندسي (Accepted & Reviewed)
- **السياق:** تتطلب المرحلة 5B فهرسة دائمة للملفات لتوفير بحث لحظي باللغتين العربية والإنجليزية وتفادي إعادة فحص كامل وسائط التخزين في كل مرة، مع الحفاظ على عمر البطارية واستجابة واجهة المستخدم، وتحديث الفهرس تلقائياً عند إجراء أي عملية (إنشاء، نسخ، نقل، حذف، إعادة تسمية)، وتنفيذ مهام خلفية مجدولة دون استخدام أي سقوط تدميري لقاعدة البيانات (`fallbackToDestructiveMigration`).
- **المراجعة الهندسية وقرار FTS4 مقابل FTS5:**
  - **الواقع التقني لـ Room و SQLite في أندرويد:**
    1. مكتبة Android Jetpack Room الرسمية تدعم حصرياً `@Fts3` و `@Fts4` ولا تقدم أي تعليق برمجي `@Fts5` في حزمتها البرمجية (`androidx.room`).
    2. إصدارات نظام أندرويد الأصلية من Android 7.0 (API 24 وهو الـ minSdk للتطبيق) وحتى Android 8.1 لم تُفعل راية `SQLITE_ENABLE_FTS5` في محرك `libsqlite.so` المدمج بالنظام؛ وبالتالي فإن محاولة استدعاء FTS5 عبر الاستعلامات المباشرة دون حزم محرك SQLite خارجي مخصص يؤدي إلى انهيار التطبيق بـ `android.database.sqlite.SQLiteException: no such module: fts5`.
    3. لتجنب تضخيم حجم حزمة التطبيق بما يفوق 15 ميجابايت من ملفات NDK المجمعة وتفادي تجاوز محرك Room الرسمي، تم اعتماد `@Fts4(contentEntity = IndexedFileEntity::class, tokenizer = FtsOptions.TOKENIZER_UNICODE61)` رسمياً مع محفزات المزامنة الخارجية التلقائية `room_fts_content_sync`.
    4. يتيح مجزئ الكلمات `unicode61` دعماً كاملاً وفورياً لتقسيم الكلمات والمحارف العربية والشرق أوسطية واللاتينية، ويحقق نفس أهداف الأداء والسرعة اللحظية دون التضحية بالتوافقية على أي إصدار أندرويد من API 24 وحتى API 36.
- **القرارات المعمارية المعتمدة والتصحيحات:**
  1. **هوية الملفات ومنع التكرار (Deduplication):**
     - استخراج المسار الحقيقي الحقيقي عبر عمود `MediaStore.MediaColumns.DATA` بدلاً من الاكتفاء بـ URI.
     - إضافة استعلام الفحص المزدوج `findByNameAndSize(name, size)` لمنع إدراج سجلات وسائط مكررة للملفات المفهرسة مسبقاً عبر وحدة التخزين الفيزيائية أو SAF.
  2. **الحذف التزايدي المقيد والآمن (Scoped Incremental Deletion):**
     - تتبع المجلدات المفتوحة والمفحوصة فعلياً `verifiedParentDirectories`.
     - حظر حذف أي سجلات إذا أُلغي الفحص في المنتصف (`isCancelledFlag`).
     - حظر حذف أي ملفات في مجلدات تعذر قراءتها أو سُحبت صلاحياتها أو أُلغي تركيب وحدات التخزين الخاصة بها (SD Card / USB OTG).
  3. **البحث الهجين (Hybrid Search: FTS4 + LIKE Fallback):**
     - مطابقة البادئات والكلمات بسرعة FTS مع البادئة `word*`.
     - مسار احتياطي عبر استعلام LIKE لمطابقة المقاطع الجزئية الداخلية للكلمات العربية والإنجليزية والامتدادات.
  4. **سياسة الجدولة وحظر التزامن في WorkManager:**
     - استخدام `ExistingPeriodicWorkPolicy.KEEP` لمنع تصفير دورة الجدولة عند كل تشغيل للتطبيق.
     - حماية عمليات الفهرسة بقفل ثنائي غير حاصر `Mutex.tryLock()` لمنع تشغيل مهمتين متزامنتين على نفس وسائط التخزين.
