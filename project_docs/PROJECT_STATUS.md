## 3. سجل إنجاز المرحلة 5A (محرك الملفات وواجهات التخزين - Storage Engine & File CRUD)
- **محرك واجهات التخزين و SAF و MediaStore (`data/local/storage/`):**
  - بناء `SafManager.kt`: إدارة أذونات الـ URI الدائمة (`takePersistableUriPermission` و `releasePersistableUriPermission`)، والتحقق من سريان الصلاحيات أو سحبها، والاستعلام المباشر عبر `DocumentsContract` و `ContentResolver` لتفادي بطء DocumentFile التقليدي.
  - بناء `MediaStoreManager.kt`: استعلام وتصفح وسائط الصور، الفيديوهات، والصوتيات وملفات التنزيل العامة والملفات الأخيرة عبر `MediaStore API` الرسمي.
- **توسيع مستودع التخزين (`domain/repository/` و `data/repository/`):**
  - توسيع `StorageRepository.kt` ليشمل عقود عمليات الإنشاء، الحذف، إعادة التسمية، النسخ الآمن، النقل الآمن، والتحكم بأذونات SAF.
  - تنفيذ `StorageRepositoryImpl.kt`:
    - معالجة ذكية لاكتشاف وحدات التخزين (`StorageVolume`) تراعي الفروقات بين إصدارات أندرويد (API 24 حتى API 36) وحساب السعات بدقة عبر `StatFs`.
    - استراتيجية النسخ الآمن (Safe Copy & Replace): التدفق المباشر عبر مصفوفة بحجم 64KB، الكتابة في ملف مؤقت `.tmp`، التحقق الصارم من سلامة البايتات والحجم قبل التثبيت الذري، وعدم فقدان البيانات عند حدوث أي خطأ.
    - استراتيجية النقل الآمن (Safe Move): محاولة النقل الذري على نفس وحدة التخزين أولاً، أو النسخ والتحقق الشامل من السلامة قبل حذف المصدر (Cross-volume move).
    - إدارة التعارض والأسماء المكررة: دعم استراتيجيات `AUTO_RENAME` (مثل `file (1).ext`)، و `OVERWRITE`، و `SKIP`.
- **فصل المسؤوليات وإدارة الحالة (Clean Architecture & MVVM):**
  - إنشاء `FilesUiState.kt` و `FilesViewModel.kt`: إدارة مسار التصفح، شريط المسار التفاعلي، تدفق القوائم، العمليات الحقيقية، والتحكم بالنوافذ الحوارية.
  - ترقية `FilesScreen.kt`: ربط الواجهة الحقيقية بـ `FilesViewModel`، شريط مسار تفاعلي، زر FAB لإنشاء مجلد أو ملف جديد، قوائم خيارات (تفاصيل، إعادة تسمية، حذف مع تأكيد)، ومعالجة زر الرجوع للتنقل التراجعي بين المجلدات.
  - ترقية `HomeScreen.kt`: قراءة أحجام التخزين الحقيقية ديناميكياً من `StorageRepository` بدلاً من القيم الثابتة.
