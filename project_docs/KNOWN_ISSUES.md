# XFiles Pro — KNOWN ISSUES & CONSTRAINTS (المشكلات والتحديات الهندسية المفتوحة)

يوثق هذا الملف التحديات التقنية، والقيود المفروضة من نظام تشغيل أندرويد، ومخاطر الأداء التي يجب مراعاتها والتعامل معها بحذر أثناء تنفيذ المراحل البرمجية.

---

### 1. قيود التخزين المقيد (Scoped Storage on Android 11+ / API 30+)
- **الوصف:** يفرض أندرويد قيوداً صارمة على الوصول المباشر إلى مسارات نظام الملفات التقليدية (`java.io.File`)، خاصة المجلدات الحساسة مثل `Android/data` و `Android/obb`.
- **الحل الهندسي المخطط:**
  - استخدام MediaStore API للملفات العامة والوسائط (صور، فيديو، صوت، تنزيلات).
  - استخدام Storage Access Framework (SAF) مع `Intent.ACTION_OPEN_DOCUMENT_TREE` و `takePersistableUriPermission` للحصول على إذن وصول دائم للمجلدات الخارجية وبطاقات SD.
  - دعم مسارات `java.io.File` كمسار سريع (Fast Path) أينما سمح النظام بذلك لتقليل التأخير الناتج عن SAF.

---

### 2. بطء التكرار في SAF مع المجلدات الضخمة (SAF Performance Overhead)
- **الوصف:** استدعاءات `DocumentFile.listFiles()` بطيئة جداً عند فحص مجلدات تحتوي على آلاف العناصر مقارنة بـ `File.listFiles()`، نظراً لأن كل استدعاء يمر عبر الـ IPC والـ ContentProvider.
- **الحل الهندسي المخطط:**
  - الاستعلام المباشر عبر `ContentResolver.query` على مستوى أعمدة الـ DocumentProvider بدلاً من إنشاء كائنات `DocumentFile` لكل عنصر على حدة.
  - تخزين نتائج الفحص في قاعدة بيانات الفهرس الدائم (Room Database) لعرضها فورياً دون الحاجة لإعادة الاستعلام.

---

### 3. تأخر تحديثات MediaStore لدى بعض واجهات OEM
- **الوصف:** بعض أجهزة أندرويد المعدلة قد تتأخر في إطلاق أحداث `ContentObserver` عند تعديل أو حذف الملفات خارج التطبيق.
- **الحل الهندسي المخطط:**
  - توفير آلية فحص تزايدي دورية خفيفة عبر `WorkManager`.
  - توفير زر تحديث يدوي فوري (Pull-to-refresh / SwipeRefresh) لمزامنة المجلد المعروض عند الطلب.

---

### 4. استهلاك الذاكرة العشوائية عند قراءة الأرشيفات والملفات الضخمة
- **الوصف:** محاولة فك ضغط أو قراءة أرشيفات بأحجام غيغابايت قد يؤدي إلى `OutOfMemoryError`.
- **الحل الهندسي المخطط:**
  - استخدام التدفق المباشر للبيانات عبر `ZipInputStream` و `BufferedInputStream` مع مصفوفة مؤقتة (Buffer) ذات حجم ثابت (64KB أو 128KB).
  - عدم تحميل الملفات بالكامل في الذاكرة نهائياً.

---

### 5. إدارة الموارد المشفرة في الخزنة
- **الوصف:** تشفير الملفات ونقلها للخزنة يجب ألا يترك بقايا من الملف الأصلي قابلة للاسترجاع عبر برامج استعادة المحذوفات.
- **الحل الهندسي المخطط:**
  - تطبيق بروتوكول الحذف الآمن (Secure Shredding) بكتابة بايتات عشوائية (Zeroing/Random bytes) على كتلة الملف الأصلي قبل استدعاء أمر الحذف النهائي، في الحالات التي يدعم فيها نظام الملفات الكتابة المباشرة.

---

### 6. التوافق المزدوج للغات بين Compose وإعدادات النظام (Per-App Language Preferences)
- **الوصف:** بدءاً من Android 13 (API 33)، وفر النظام ميزة إعدادات اللغة لكل تطبيق عبر إعدادات النظام (`android.app.LocaleManager`). يعتمد حلنا الحالي على `LocalizedApp` في Compose عبر `createConfigurationContext` و `LocalLayoutDirection` لتفادي إعادة إنشاء النشاط (Activity Recreation) ومنع فقدان حالة المستخدم.
- **الحل الهندسي:** الحل الحالي يعمل بنجاح 100% على كافة الإصدارات من API 24 وحتى API 36، وفي حال الرغبة بربط التفضيل أيضاً مع إعدادات نظام أندرويد 13 الخارجية دون إعادة تشغيل، يمكن استدعاء `LocaleManager.setApplicationLocales` بالتوازي بعد التحقق من إصدار النظام `Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU`.


---

### 7. منع تعدد نُسخ DataStore لنفس ملف التفضيلات (DataStore Singleton Invariant)
- **الوصف:** تفرض مكتبة Jetpack DataStore قاعدة صارمة بأن يكون لكل ملف تفضيلات (`.preferences_pb`) كائن DataStore وحيد (Singleton) داخل العملية الواحدة، وأي محاولة لاستدعاء مفوض `preferencesDataStore` باسم الملف نفسه أكثر من مرة ستؤدي إلى استثناء فوري `IllegalStateException: There are multiple DataStores active for the same file`.
- **الحل الهندسي المنفذ:** تم تعريف `Context.dataStore` مرة واحدة مركزياً، وتقوم كل من `LanguagePreferences` و `ThemePreferences` بإعادة استخدام نفس الكائن المشترك وتمريره في الحاوية المركزية `AppContainer` ومستودعات البيانات، مما يضمن التزامن التام والتماسك وانعدام أي تضارب في القراءة والكتابة.
