# XFiles Pro — MASTER CONTEXT (السياق العام والمرجعي للمشروع)

## 1. التعريف بالمشروع (Project Identity)
- **اسم التطبيق (App Name):** XFiles Pro
- **نوع التطبيق (Category):** مدير ملفات متقدم وشامل لنظام أندرويد (Professional Android File Manager).
- **الهدف الاستراتيجي:** بناء مدير ملفات متكامل وقوي ينافس التطبيقات الرائدة في هذا المجال (مثل MiXplorer Silver وSolid Explorer)، مع تجربة مستخدم عصرية تعتمد على Material Design 3 وتوفر أداءً استثنائياً وأماناً صارماً.
- **طبيعة المشروع:** مشروع برمجي طويل الأمد ومؤسسي، وليس مجرد نموذج أولي أو تطبيق تجريبي. جميع الميزات المضمنة يجب أن تكون وظائف حقيقية وقابلة للاستخدام بنسبة 100%.
- **الشعار التسويقي:** لا يوجد شعار تسويقي معتمد حتى الآن (يُمنع اختراع شعار تسويقي أو علامة تجارية نهائية دون موافقة مسبقة من المستخدم).

---

## 2. المبادئ الهندسية الأساسية (Core Engineering Principles)
1. **فصل المسؤوليات (Separation of Concerns):** الفصل التام بين طبقة واجهة المستخدم (UI/Jetpack Compose)، وطبقة منطق الأعمال (Domain/Use Cases)، وطبقة الوصول للبيانات (Data/Repositories/Room/SAF).
2. **استقلالية الوحدات (Modularity):** بناء ميزات التطبيق كوحدات مستقلة وقابلة لإعادة الاستخدام والاختبار.
3. **منع تجميد الواجهة (Non-blocking I/O):** تنفيذ جميع عمليات الإدخال والإخراج وقراءة الملفات وفهرستها وحساب الهاش ونقل البيانات داخل خيوط خلفية غير متزامنة عبر Kotlin Coroutines (`Dispatchers.IO`).
4. **كفاءة الذاكرة والأداء (Memory & Performance):** إدارة حذرة لموارد الذاكرة، دعم القراءة بالتدفق (Streams / Buffers)، التحميل التدريجي للملفات والصور المصغرة، وتجنب تحميل الملفات الضخمة بالكامل في الذاكرة.
5. **منع الأكواد الضخمة (No Monolithic Files):** تقسيم الملفات بحيث تظل مركزة وموجزة (تجنب تخطي 500 سطر للملف الواحد)، مع تنظيم دقيق للحزم.
6. **معالجة صارمة للأخطاء (Defensive & Clear Error Handling):** استخدام أنواع معبرة ومغلفة للنتائج (`Result<T>` أو `DataState<T>`) دون ابتلاع الأخطاء أو التسبب في انهيار التطبيق (Crashes).
7. **منع البيانات الوهمية (Zero Mock Data in Production):** التعامل مع نظام الملفات الحقيقي ونظام Android Storage Access Framework وMediaStore بدون استبدالها ببيانات تجريبية مصطنعة.
8. **الأمان وحماية الخصوصية (Zero-Trust Privacy & Security):** استخدام أدنى الصلاحيات المطلوبة، تشفير آمن عبر Android Keystore، عدم رفع أي ملفات أو بيانات اعتماد إلى خوادم خارجية، والتعامل الآمن مع Content URIs.

---

## 3. العمل محلياً وبدون إنترنت (Offline-First Architecture)
- يعمل التطبيق بكامل وظائفه الأساسية (تصفح، إدارة، فهرسة، بحث، عارض ملفات، خزنة، ضغط وفك أرشيفات، تحليل سعة) بشكل محلي 100% دون الحاجة إلى اتصال بالإنترنت أو الاعتماد على خادم سحابي إجباري.
- تتطلب ميزات الشبكة (نقل Wi-Fi، وبروتوكولات FTP / SFTP / SMB / WebDAV، ومدير التنزيل) الاتصال فقط أثناء استخدامها من قبل المستخدم.

---

## 4. نظام التوثيق الدائم واستمرارية التطوير (Project Documentation & Continuity)
- يمثل مجلد `project_docs/` المصدر الدائم والوحيد للحقيقة الهندسية للمشروع.
- عند تبديل جلسة العمل، أو تغيير الحساب، أو استبدال نموذج الذكاء الاصطناعي، يجب الرجوع إلى ملفات التوثيق العشرة لفهم بنية المشروع وتحديد آخر مرحلة مكتملة والانطلاق مباشرة من `NEXT_TASK.md` دون تكرار أو إعادة بناء عشوائي.
- يجب تحديث ملفات التوثيق بانتظام بعد إنجاز كل مرحلة أو اتخاذ قرار هندسي جوهري.
